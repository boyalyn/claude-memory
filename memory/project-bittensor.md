**Bug found & fixed 2026-10-13 05:20 UTC (mine):** RedditContent.to_data_entity() mutates created_at/scraped_at IN PLACE (entity.datetime keeps seconds on first call, truncated on later calls). The cache in reddit_od_apify.py reused stored objects, so every serve after the first sent entities whose datetime lacked seconds -> validator "DataEntity fields are incorrect" (6/40 cached sample failed; with limit=1 the same top post is re-served, so most Reddit answers from the caching deploy ~21:25 UTC Oct 12 to 05:20 UTC Oct 13 were probably invalid). Fix: serve `c.copy(deep=True)`; loader drops posts with created_at seconds==0. After fix 28/28 second-serve entities validated. OD bad submissions cost 5% OD credibility each, so the emission drop 0.0072->0.0031 plausibly stems from this (not proven). Lesson: validate a sample of what is actually served with the scraper's own validate() before deploying data-path changes.

**Validator OD evaluation detail (repo vali_utils/miner_evaluator.py, verified 2026-10-13):** each validator evaluates a miner at most every 60 min; per eval it samples up to 3 non-empty submissions and runs THREE phases: (1) schema/format + duplicates, (2) job match (_validate_request_fields: subreddit/keywords/usernames in text, time window), plus metadata completeness, (3) scraper re-check of 1 entity. Pass => od_boost EMA(0.3) toward 100M*speed*volume and cred +2%; fail => od_boost x0.7, cred -5%. volume mult = (returned/limit)^1.3. My earlier "45/45 valid" tests only covered phase 3 and missed phase 2. Phase-2 test of real X output: ~34-60% of apidojo actor results for keyword jobs FAIL the keyword-in-text check (actor matches elsewhere), so submitting results[0] failed often. Fix deployed 2026-10-13 ~10:57 UTC: scraping/od_preflight.py runs the validator's own functions on every entity before submit (X preflight before limit truncation), X jobs with limit>50 are skipped without scraping, answers filled <50% of limit are dropped, Reddit picks safest posts first (>=72h old, empty body). Reddit large sample: 157/160 pass phase 3 (failures: body mismatch on posts with bodies, one comment-count drift). Rule for the future: test ALL validator phases (use the validator's own functions with a stub evaluator), not just the scraper re-check.

**Request statistics & adaptive long-tail threshold (2026-10-13 11:10 UTC, VPS):** scraping/od_request_stats.py records every OD request (Reddit key = subreddit, X key = normalized keywords@usernames) to ~/data-universe/od_requests.jsonl and keeps decayed counts (half-life 24h) in od_request_stats.json. Threshold T is read from the distribution: smallest count c in [1,6] where continuation prob r(c)=#keys(count>=c+1)/#keys(count>=c) >= 0.5 (P_STAR); cold start T=2 until 500 obs and 6h history. is_tail(key)=count+0.25<T; Reddit module spends Apify money only on non-tail subs (core head >=2T may use whole daily budget, band above T only first 60%). Observed Reddit distribution (2,018 requests, 304 subs, ~10h): 241 subs seen once, 8 seen 2-3x, 54 seen 4+; r(1)=0.20, r(2)=0.87, r(3+)=~1.0; top 40 subs ~80% of requests; T=2 -> head ~61 subs (~87% of mass). X keys are almost all unique (257 keys in 335 requests): no head/tail structure, X is recorded only. Tools: od_stats_backfill.py (seed from miner logs), od_stats_report.py [reddit|x] (distribution, coverage curve, replay of the rule, continuation probabilities).
